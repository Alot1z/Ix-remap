Thanks for the review — all three findings are fixed on the branch (head `17d2da44`, rebased on main `8c0e6b00`), plus the design note adopted.

## 1. Banner unreachable in installed layouts — fixed, and pinned so it cannot regress

- `scripts/render-logo.mjs` → `ix-cli/scripts/render-logo.mjs` and `assets/logo.png` → `ix-cli/assets/logo.png`. Both inputs now live inside the package, so `banner.ts` needs no repo-root path math at all: the dynamic import resolves relative to the compiled file in every layout.
- Verified against the two delivery paths from the finding: `npm pack --dry-run --json` now lists the renderer and the asset, and the compiled `dist/cli/banner.js` renders the banner when run from an installed-layout tree (25 banner lines, non-null) instead of silently degrading.
- Two structural pins added so this cannot silently strand again: a test asserts the pack manifest carries both inputs, and `release.yml` stages both files into `$STAGING/cli/` with a gate asserting their presence in the staging tree.
- The absent-safe contract is preserved: the loader probes for the package-relative inputs first and only then imports, so a layout without them still degrades to the plain heading (found and fixed while testing: the in-process rewrite initially made a missing renderer fatal at module load in the watch-child runtime cache — a third layout the probe now covers).

## 2. CodeQL `js/file-system-race` — fixed with the house open-once/fstat pattern

`decodePng` now opens the path once with `O_NONBLOCK`, `fstat`s **the handle**, checks `isFile()` and size on that stat, and reads from the same fd. The stat-then-read TOCTOU is gone, FIFOs can no longer block the read (nonblocking open rejects them via the `isFile()` check), and the size guard now applies to the file actually read.

## 3. Preview PNGs — dropped from the PR tree

Both `output-samples/banner-*.png` files are removed from the branch. The `.ans` goldens (byte-pinned by `bootstrap-notice.test.ts`) stay. The preview PNGs live on a separate `meta/logo-previews` branch and the PR description links them there, so the PR tree carries only what ships.

## Design note — adopted

`renderBanner()` now imports the renderer in-process (dynamic import, no subprocess, no spawn cost), behind the absent-safe probe above.
