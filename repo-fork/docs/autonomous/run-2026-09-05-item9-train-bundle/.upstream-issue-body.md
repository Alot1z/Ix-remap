## Problem

`scripts/install-skill.sh` prints one line per harness, and on a machine with
several harnesses the lines are distinguishable only by a substring buried
mid-path:

```
would install: /home/user/.claude/skills/ix
would install: /home/user/.agents/skills/ix
would install: /home/user/.codex/skills/ix
would install: /home/user/.cursor/skills-cursor/ix
```

Reading a dry run (or a CI log of one) means parsing paths by eye. The harness
id — the thing a user would actually pass on the command line — appears
nowhere in the human output, though it is in hand in the install loop and in
every `--json` record.

A second gap: at the end of a run, the footer reports only counts
(`Ix skill installed for 3 harness(es).`). There is no compact per-host
accounting of what happened — including **skips and refusals**, which are the
interesting outcomes (a refusal means a foreign skill was protected and the
user should know where).

## Evidence

Recorded in a hermetic demo run of the merged installer (2026-09-05):

- Four near-identical `would install:` lines; the harness ids appear only in
  the `--json` report, never in human output.
- The refusal path prints its message inline during the loop and is easy to
  miss when several hosts install before it.
- `--json` exists and is honest, but nothing in the human output mentions it
  (that part is already fixed on the branch above via `--help` + a dry-run
  footer hint; kept separate here so this issue stays about the two output
  changes).

## Minimal fix (output text only — no behavior, no flags, no exit-code changes)

**1. Label the install/dry-run lines with the id:**

```
would install [claude]: /home/user/.claude/skills/ix
Installed [codex]: /home/user/.codex/skills/ix
```

Cost: the id is already in scope at both `say` sites.

**2. Print a per-host summary table from the existing `DECISIONS` records
before the footer** (no new state — the array already holds
`id/action/dest/via`):

```
Harness   Action     Destination                    Detected via
claude    installed  ~/.claude/skills/ix            path
agents    installed  ~/.agents/skills/ix            config-dir
codex     skip       —                              none
cursor    refused    ~/.cursor/skills-cursor/ix     config-dir
```

Destinations print `~`-folded to keep lines short; the absolute path stays in
`--json`. Skips and refusals appear with their real action so the table is
honest, not promotional.

## Compatibility notes (checked)

- CI's two smoke assertions grep `would install: …` verbatim
  (`ci.yml` harness-install-smoke jobs). Change 1 must update those greps in
  the same PR — included in the branch so the output contract stays pinned.
- `--json` consumers are unaffected: field-based assertions, shape unchanged.
- Deliberately **not** proposed here: a `--prefix`/root flag (HOME redirection
  is already the hermetic seam), progress spinners, and colored output (CI
  greps raw lines).
